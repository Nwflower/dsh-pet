这次把宠物设置页并进了 Web 扩展父级，宠物选择换成可视化预览卡，有界的数值字段加上粗调滑杆，启用开关也搬到卡片标题栏。同时跟上家族统一的 0.4.11 版本号。

> **兼容性**：没有破坏性变更，也无需手工迁移。包名 `@linxin666/dsh-pet` 与安装方式不变；`dsh.engines.dsh` 的声明与下限本轮不动，仍是 `>=0.2.1-rc.3`，peer 依赖下限同样不动。持久化标识不变：布局与游戏进度仍写在 `$DSH_HOME/pet.json`，键名一个不改；宠物资产仍落在 `$DSH_HOME/pets/<id>/`；语音包分层仍是宠物 `voice.json` > 全局 `$DSH_HOME/pets/.voice.json` > 内置。线协议字段不变，设置字段名（`petId`、`statusBubbles` 等）也不变，旧配置文件直接可用。没有 Web 扩展父级的独立安装保留原来的一级设置分区，入口与行为与 0.4.10 一致。

### 设置页并入 Web 扩展

- 宠物设置页优先注册进 Web 扩展父级的按 key 挂载位（key `pet`）；父级缺席时回落到原来的一级 `settings.section`（id `pet`、order 130）。两处互斥，任一时刻只有一个可达入口，独立安装因此不会丢设置页
- 跟随 `slots/changed` 只做一次协调：先释放旧注册再登记新座位，并对同步重入加护栏；表单控制器挂在 `apply()` 上而不属于任何座位，所以换座位既不丢已编辑的草稿，也不重复请求宠物注册表
- 设置根节点带语义标记 `data-dsh-plugin="pet"`，皮肤可以据此定位这一页，而不必依赖一级导航的位置

### 设置卡片改为两栏可视化

- 左栏是可点选的可视化宠物卡，缩略图直接用注册表已经在发的图集首帧或 frames2d 静帧，不新增第二条资产通道；live2d 与缺少图集字段的老宿主退化为文字标记而不是裂图。右栏是分组后的显示与行为字段，容器变窄时整页回落成单栏
- 启用开关上移到卡片标题栏，说明文案同时缩短
- 有界数值字段旁挂粗调气泡：指针停留或焦点进入后，弹出覆盖该字段整个取值范围的滑杆，一次拖动就能跨过很大一段；控件本身仍是精确输入。拖动时实时回显，松手或按键才提交一次；气泡按最近的滚动祖先挑选有空间的一侧展开，靠近页首的行也不会挂到页面外

### 其他改动

- 共享组件：分段控件统一成家族样式，一条安静的轨道加一块滑动的高亮，设置页的小选项与 Web 扩展的 TAB 条共用同一个控件，两处读起来是一套
- 布局：跟随共享卡片的控件列宽上限，控件不再撑破列
- 测试：新增 `src/client/settings-registration.test.ts` 钉住动态迁移——座位切换、旧注册先释放、控制器不被重建；设置表单与回落行为仍由既有用例覆盖，可视化选择卡的挂载断言写在 `tests/pet-section.spec.tsx`
- 文档：README 中英双语同步改写设置入口的描述，`README.i18n.yaml` 的校验记录一并更新
- 版本：`package.json` 的 `version` 从 0.4.10 抬到 0.4.11，与 dsh-web 家族统一版本号对齐（卫星先发、主仓后发）
- `lib/` 不入库（在 `.gitignore` 里），由 `prepare` 脚本在发布时现场重建，因此本次没有随之改动的已提交产物；本说明文件不在 npm 包的 `files` 白名单里，不会进入发布产物

This release seats the pet settings page inside the Web Extensions parent, replaces the pet selector with visual preview cards, adds coarse sliders to the bounded numeric fields, moves the enable switch into the card header, and carries the family version number to 0.4.11.

> **Compatibility**: nothing breaks and no manual migration is needed. The package name `@linxin666/dsh-pet` and the install path are unchanged; the `dsh.engines.dsh` declaration and its floor stay untouched this cycle at `>=0.2.1-rc.3`, and so do the peer-dependency floors. Every persistence identifier keeps its name: layout and gameplay progress still live in `$DSH_HOME/pet.json` with identical keys, pet assets still land in `$DSH_HOME/pets/<id>/`, and voice-pack layering is still pet `voice.json` > global `$DSH_HOME/pets/.voice.json` > built-in. Wire-protocol fields are unchanged, and so are the settings field names (`petId`, `statusBubbles` and the rest), so an existing configuration file keeps working as written. A standalone install without the Web Extensions parent keeps its original first-level settings section, with the same entry and behaviour as 0.4.10.

### The settings page joins Web Extensions

- The pet settings page registers into the Web Extensions parent's keyed seat (key `pet`) whenever that parent exists, and falls back to its original first-level `settings.section` (id `pet`, order 130) when it does not. Exactly one entry is reachable at a time, so a standalone install never loses its settings page
- One reconciliation loop follows `slots/changed`: it disposes the old registration before registering the replacement, and guards synchronous re-entry. The form controller belongs to `apply()` rather than to either seat, so a seat migration neither discards staged edits nor repeats the pet-registry request
- The settings root carries the semantic `data-dsh-plugin="pet"` marker, so skins can identify the page without depending on first-level navigation positions

### The settings card becomes a two-column visual layout

- The left column offers clickable visual pet cards whose thumbnails come from the very atlas or frames2d still frame the registry already serves, so no second asset channel is added; live2d and older hosts that omit the atlas fields degrade to a text mark instead of a broken image. The right column holds grouped display and behavior fields, and the whole page collapses to one column when the container narrows
- The enable switch moves into the card header and its copy is shortened
- Each bounded numeric field gains an adjustment bubble: once the pointer rests on it or focus enters it, a slider spanning that field's whole range appears, so a large change is one drag rather than many presses; the control itself stays the precise entry. Dragging reports the value live and releasing the thumb or pressing a key commits once. The bubble opens on the side of the control that has room inside the nearest scrolling ancestor, so a row near the top of the page does not hang it past the page edge

### Other Changes

- Shared components: the segmented control becomes the family style — one quiet track with a single highlight that slides — and both the settings fields' small choices and the Web Extensions TAB strip render through it, so the two read as one control
- Layout: the shared card's control column-width cap is followed, so controls no longer overflow their column
- Tests: `src/client/settings-registration.test.ts` is added to pin the dynamic migration — the seat switch, the old registration being released first, and the controller not being rebuilt; the existing suites still cover the settings form and the fallback behaviour, and the visual-choice mount assertion lives in `tests/pet-section.spec.tsx`
- Docs: the English and Chinese READMEs are rewritten together for the new settings entry, and the `README.i18n.yaml` verification record is updated with them
- Version: `version` in `package.json` moves from 0.4.10 to 0.4.11 to follow the unified dsh-web family version (satellites ship first, the main repository follows)
- `lib/` is not tracked (it sits in `.gitignore`) and is rebuilt on the spot by the `prepare` script at publish time, so no committed artifact moves with this release; this notes file is outside the npm package's `files` whitelist and never reaches the published artifact

宠物插件随 dsh-web 家族对齐到统一版本，本次只搬版本号：本仓自 v0.4.9 发布以来没有任何源码改动，0.4.10 是一次纯粹的家族对齐。

> **兼容性**：没有破坏性变更，也无需手工迁移。包名 `@linxin666/dsh-pet` 与安装方式不变；持久化标识不变（布局与游戏进度仍写在 `$DSH_HOME/pet.json`，键名一个不改；宠物资产仍落在 `$DSH_HOME/pets/<id>/`；语音包分层仍是宠物 `voice.json` > 全局 `$DSH_HOME/pets/.voice.json` > 内置）；线协议字段不变；`dsh.engines.dsh` 的声明与下限本轮同样不动，仍是 `>=0.2.1-rc.3`。因此 0.4.9 的安装可以直接升级，回退到 0.4.9 也不需要迁移数据。

### 其他改动

- 版本对齐：`package.json` 的 `version` 从 0.4.9 抬到 0.4.10，只为跟随 dsh-web 家族的统一版本号（卫星先发、主仓后发），没有功能、测试或资产的改动
- 发布产物与 0.4.9 二进制等价，唯一的差异是构建期从 `package.json` 烙进客户端包的版本字符串：`shared/tsdown.client.ts` 读 `manifest.version` 并把它写进产物，于是烙入值从 0.4.9 变成 0.4.10；除这一处字符串外，压缩后的模块体、导出表与类型声明逐字节相同
- 仓库里没有随之改动的已提交产物：`lib/` 不入库（在 `.gitignore` 里），发布时由 `prepare` 脚本现场重建，因此本次提交只有 `package.json` 与本文件
- 行为不变量：亲和度积分、奖励、冷却与已持久化的账本、宠物渲染与拖拽位置、设置表单与公告位、配对信任围栏都与 0.4.9 完全一致；本说明文件不在 npm 包的 `files` 白名单里，不会进入发布产物

This release aligns the pet plugin with the unified dsh-web family version and moves nothing but the version number: this repository has had no source change since v0.4.9 shipped, so 0.4.10 is a pure family alignment.

> **Compatibility**: nothing breaks and no manual migration is needed. The package name `@linxin666/dsh-pet` and the install path are unchanged; every persistence identifier keeps its name (layout and gameplay progress still live in `$DSH_HOME/pet.json` with identical keys, pet assets still land in `$DSH_HOME/pets/<id>/`, and voice-pack layering is still pet `voice.json` > global `$DSH_HOME/pets/.voice.json` > built-in); wire-protocol fields are unchanged; and the `dsh.engines.dsh` declaration and its floor stay untouched this cycle at `>=0.2.1-rc.3`. An existing 0.4.9 installation can upgrade in place, and going back to 0.4.9 needs no data migration either.

### Other Changes

- Version alignment: `version` in `package.json` moves from 0.4.9 to 0.4.10 purely to follow the unified dsh-web family version (satellites ship first, the main repository follows), with no functional, test or asset change
- The published artifact is binary-equivalent to 0.4.9 apart from one version string baked in at build time: `shared/tsdown.client.ts` reads `manifest.version` into the client bundle, so the baked value changes from 0.4.9 to 0.4.10; beyond that string, the minified module bodies, the export tables and the type declarations are byte-identical
- No committed artifact moves with it: `lib/` is not tracked (it sits in `.gitignore`) and is rebuilt on the spot by the `prepare` script at publish time, so this commit contains only `package.json` and this file
- Behaviour invariants: affinity points, rewards, cooldowns and the persisted ledger, pet rendering and dragged positions, the settings form and the announcement slot, and the pairing trust fence are all identical to 0.4.9; this notes file is outside the npm package's `files` whitelist and never reaches the published artifact
